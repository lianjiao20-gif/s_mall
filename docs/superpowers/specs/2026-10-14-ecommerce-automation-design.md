# 小型电商自动化案例设计

## 目标与范围

构建可在本地重复运行的单店铺电商案例，供用户自行编写 REST 接口测试与浏览器 UI 自动化。交付范围为可启动的电商前后端、数据库结构、演示数据和使用文档；不交付接口自动化或 UI 自动化测试代码。购物用户可登录、浏览和搜索商品、查看详情、维护购物车、模拟结算，以及查询自己的订单。支付仅模拟成功，不接入外部支付服务。项目不包含后台管理、优惠券、配送或真实支付。

## 技术架构

- `apps/web`：Vite、React、TypeScript。调用独立 REST API，提供响应式页面。
- `apps/api`：Node.js、Express、TypeScript、mysql2。负责认证、业务规则、数据库访问和一致的错误响应。
- MySQL 8 由 Docker Compose 提供。SQL 迁移和种子脚本创建结构、演示账号与固定商品。
- 提供可重复执行的数据库初始化与演示数据脚本。账号、商品和预期价格记录在 README 中，供用户编写自己的自动化用例。

前端和 API 分别启动。前端开发服务器代理 `/api` 到后端；浏览器与测试统一使用相对路径，避免环境地址散落在页面代码中。

## 用户流程

1. 访问首页，查看商品列表；可按名称搜索，进入商品详情。
2. 使用演示账号登录。未登录时仍可浏览商品，操作购物车或订单会引导登录。
3. 在详情页加入购物车，在购物车页修改数量或移除商品。
4. 提交订单。API 在事务中锁定相关商品、检查库存与数量、保存单价快照、扣减库存、创建订单及明细、清空购物车。
5. 在订单页查看订单列表与明细。支付状态标为模拟支付完成。

页面保留明确的加载、空状态与失败提示；交互控件使用可访问名称，方便用户与 Playwright 稳定定位。

## 数据模型

- `users`：ID、邮箱、密码哈希、名称。
- `products`：ID、名称、描述、分类、价格（整数分）、库存、图片路径、是否上架。
- `cart_items`：用户 ID、商品 ID、数量；用户与商品组合唯一。
- `orders`：ID、用户 ID、总价（整数分）、状态、创建时间。
- `order_items`：订单 ID、商品 ID、名称快照、单价快照、数量。

金额使用整数分计算。商品图片作为仓库内静态资源，数据与界面均不依赖第三方服务。

## API 契约

所有响应为 JSON，业务错误使用 `{ error: { code, message } }`。认证使用登录取得的 Bearer token；购物车和订单接口必须认证。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `POST` | `/api/auth/login` | 登录 |
| `GET` | `/api/auth/me` | 当前用户 |
| `GET` | `/api/products` | 列表、搜索、分类筛选 |
| `GET` | `/api/products/:id` | 商品详情 |
| `GET` | `/api/cart` | 购物车 |
| `POST` | `/api/cart/items` | 加入商品 |
| `PATCH` | `/api/cart/items/:productId` | 修改数量 |
| `DELETE` | `/api/cart/items/:productId` | 移除商品 |
| `POST` | `/api/orders` | 从购物车下单 |
| `GET` | `/api/orders` | 当前用户订单 |
| `GET` | `/api/orders/:id` | 当前用户订单详情 |

输入由 API 校验；无效输入返回 400，未认证返回 401，未找到或非本人订单返回 404，库存不足等业务冲突返回 409。数据库异常返回 500 且不暴露内部细节。

## 可运行性与自动化接入

- 接口契约和错误码保持稳定；README 提供 API 路径、请求样例、演示凭据和固定商品数据。
- 提供数据库重置与重新填充演示数据的命令，便于用户在运行自己的测试前恢复初始状态。重置命令只作用于配置的项目数据库，并在文档中明确说明会清除该库中的业务数据。
- 提供 `.env.example`、Docker Compose、数据库初始化与种子命令、开发启动命令。README 给出从空环境运行的步骤。

## 验收标准

按照 README 启动后，演示账号可完成完整购物流程；API 返回约定状态与数据；数据库可恢复到固定演示状态。页面在常见桌面与手机宽度下可用。用户自行实现自动化测试。
